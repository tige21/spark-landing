# Секция колод лагала при скролле: четыре острова и десять 3D-контекстов на статичный список

**Date:** 2026-09-14 16:46
**Files:** src/components/sections/Decks.astro, src/components/sections/DecksShelf.astro (new), src/components/sections/DecksShelf.tsx (deleted), src/styles/tokens.css, tests/layout.spec.ts
**Severity:** medium

## Problem

Блок «Девять колод» ощутимо лагал при скролле. Содержимое блока — заголовок и
девять карточек с маркой, названием и примером вопроса. Полностью статичный
контент.

## Root Cause

Аудит вычисленных стилей в секции `#decks` (63 узла):

```
perspective   : 10 элементов  (.deck-grid + девять .deck-cell)
will-change   :  3 элемента   (reveal-tilt, обёртка Parallax, reveal decks-enter)
astro-island  :  4 острова    (Parallax, TiltIn, Reveal, DecksShelf)
pointer-хендлеров: 36         (4 × 9 карточек)
```

Четыре гидрируемых острова на статичный список. Разбор по вкладам:

1. **Въезд карточек.** `.deck-cell { transform: translateY(22px) rotateX(20deg) }`
   со стаггером требовал `perspective` и на сетке (1100px), и на каждой из
   девяти ячеек (700px). Свойство `perspective` держит 3D rendering context
   живым **всю жизнь страницы**, а не на время анимации — десять постоянных
   контекстов в одной секции.

2. **Герб-подложка.** `<Parallax rotate={8}>` крутил гравюру на ±4° при
   opacity **0.12**. Замер: отрисованный размер 597×1156 CSS px, при dpr 2 это
   растр 1194×2312. Анимированный слой лежал ПОД девятью карточками, а всё, что
   рисуется поверх композиторного слоя, компоновщик обязан поднять в слои тоже —
   сетка и заголовок становились отдельными слоями и перерисовывались весь скролл.
   Поворот на ±4° при 12% прозрачности не виден; компоновка — видна.

3. **`will-change` у `.reveal*` без ограничения** (tokens.css). Ревилы
   одноразовые, а подсказка висела вечно: каждый показанный блок оставался
   отдельным слоем до конца жизни страницы.

4. **Hover-наклон** `translateY(-8px) rotateX(-6deg)` плюс JS-напарник:
   `onPointerDown/Up/Cancel/Leave` на каждой карточке подделывали `:hover` для
   тача. Ради этого сетка и была островом.

## Solution

Пользователь попросил убрать анимации карточек и разгрузить блок — это сняло
ограничение, из-за которого прошлая попытка (2f8eaa0, отревертен c30d4d7)
пыталась сохранить анимации и чинить только слои.

1. Въезд карточек удалён целиком вместе с `perspective` на сетке и ячейках.
2. Hover отвечает только краской: `box-shadow` + `border-color`, без transform —
   карточке больше не нужен слой. Pointer-хендлеры удалены.
3. `DecksShelf.tsx` → `DecksShelf.astro`: без наблюдателя и без хендлеров это
   статический `<ul>`, остров не нужен.
4. `<Section flat>` — секции больше не нужен `TiltIn`; въезд остался только у
   заголовка (`.decks-enter`), как и просили.
5. Герб статичен: `Parallax` снят.
6. `.reveal*` → `:not(.is-in)` в tokens.css.

Замер после:

```
perspective   : 10 -> 0        will-change (после проигрыша ревила): 3 -> 0
astro-island  :  4 -> 1        pointer-хендлеров: 36 -> 0
JS на /       : 245019 -> 238764 B (-6.1 КБ, чанков 23 -> 21)
по странице   : will-change 37 -> 26, perspective 15 -> 5
```

## Prevention

- **`perspective` как СВОЙСТВО держит 3D-контекст всю жизнь страницы**, а не на
  время анимации. Для одноразового въезда это чистый убыток: девять ячеек = девять
  постоянных контекстов. Если глубина нужна только на время трансформа — она
  должна жить внутри `transform: perspective(...)`, а лучше не быть вовсе.
- **Анимированный слой ПОД контентом дороже, чем кажется.** Всё, что рисуется
  поверх композиторного слоя, само уходит в слои. Гравюра на 12% прозрачности
  утащила за собой девять карточек и заголовок. Прежде чем анимировать фон,
  посчитать, что лежит сверху.
- **`will-change` для одноразовой анимации ограничивать состоянием.**
  `.reveal:not(.is-in)` вместо `.reveal`: Chrome и так промоутит на время
  работающего транзишена, подсказка нужна только ДО старта.
- **Остров, которому нечего гидрировать, — это просто .astro.** Здесь весь JS
  сетки существовал ради анимации; убрали анимацию — остров исчез сам. Проверять
  после любого упрощения: остались ли в `.tsx` эффекты и хендлеры вообще.
- **Автоматизированный Chrome этот класс лагов не воспроизводит** (p99 кадра 9.5 мс,
  0 кадров >32 мс на заведомо тяжёлой версии — то же предупреждение уже стоит в
  патче 2026-09-12-00.20). Мерить надо РАБОТУ: число `perspective`,
  `will-change`, островов и хендлеров через `getComputedStyle` по секции — это
  воспроизводимо и попадает в тест.
- **Реверт без причины в сообщении стоит дорого.** 2f8eaa0 менял четыре вещи
  сразу; какая именно не устроила — по `git log` не восстановить, и следующая
  попытка начинается с нуля.
