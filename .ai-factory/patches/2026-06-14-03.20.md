# Decks hover jank, three.js removal, Искра logo + meta

**Date:** 2026-06-14 03:20
**Files:** src/components/sections/DecksShelf.tsx, src/components/sections/Decks.astro, src/components/hero/Hero.astro, src/components/hero/HeroContentMotion.tsx (kept), removed HeroCanvas.tsx + HeroScene.tsx, src/components/layout/Nav.astro, src/layouts/Layout.astro, src/assets/engravings/logo-seal.png, public/favicon.png, public/og.png, package.json
**Severity:** medium

## Problem

1. Decks cards "jumped" on hover — moving the cursor across the grid made cards grow/shrink and reflow neighbours.
2. The "3D hero" had no perceptible three.js payoff for the cost (893 KB lazy chunk) and the user wanted only framer-motion animations; lots of r3f code was effectively dead weight.
3. Meta/branding used a generic panorama OG and a placeholder favicon — the real Искра seal logo wasn't used anywhere.

## Root Cause

1. The deck-card sample question was revealed on hover via `max-height: 0 → 120px` + JS `active` state. Animating `max-height` changes the element's box height, so the CSS grid row re-sizes and every sibling below shifts — classic layout-shift jank, amplified by rapid hover changes.
2. three.js / @react-three/fiber / drei were a deliberate "max-wow" choice, but the visual result (faint drifting particles) didn't justify ~900 KB; the user re-scoped to framer-only.
3. Branding was built before the final logo existed.

## Solution

1. **Decks:** removed the hover/`active` reveal entirely — the sample question is now always rendered (reserved space), so hover only does a transform-based lift (`whileHover y:-6`) + box-shadow. No box-size change → zero layout shift. `.deck-card` became a `div` (no longer an interactive toggle).
2. **three.js removal:** deleted HeroCanvas/HeroScene, dropped the `client:only` WebGL island, `npm uninstall three @react-three/fiber @react-three/drei @types/three`. Hero is now a static engraving poster + the logo seal + framer content-dissolve. Heaviest chunk dropped from 893 KB (three) to ~180 KB (React).
3. **Logo:** keyed the seal PNG to a transparent circle (density-based medallion detection + circular alpha mask via PIL — flat-threshold caught paper grain, so used per-row/col density spans), wired it into nav brand, hero, `favicon.png`, and a branded `og.png` (seal + Lora wordmark composited with PIL using the self-hosted font).

## Prevention

- **Never animate `max-height`/`height`/`width`/`top`/`left` for reveals** — they trigger layout and shift siblings (especially in grid/flex). Animate `transform`/`opacity` only, and reserve space for conditionally-shown content.
- Match animation tech to payoff: a heavy 3D dependency must earn its bundle cost; prefer CSS/framer transforms for "ambient" motion.
- When keying a logo whose interior shares the background colour (cream seal on cream paper), a flat colour-distance key fails on grain — detect the shape (row/col density / bbox) and mask geometrically instead.
