# Один флинг проносил мимо всей демонстрации игры на мобильном

**Date:** 2026-09-18 11:05
**Files:** src/components/sections/ThroughPhone.tsx, tests/layout.spec.ts
**Severity:** high

## Problem

После сокращения пина секции с телефоном (9841 → 3629 px на 390×844) одного
маха пальцем хватало, чтобы проскочить секцию целиком: посетитель не видел ни
одного из трёх экранов приложения. Нативный scroll-snap, который должен
останавливать на каждом действии, не срабатывал.

## Root Cause

Две причины наложились.

1. **Шаг стал короче порога флинга.** `perAction` на мобильном опустили
   0.82 → 0.55, то есть 464 px на действие при высоте экрана 844. Инерционный
   бросок проходит 2–3 экрана, шесть таких шагов укладываются в один жест.

2. **Снап взводился слишком поздно — и это главное.** Класс `html.tp-snap`
   переключался внутри обработчика прогресса: `p > 0.005 && p < 0.995`, то есть
   только когда секция уже под вьюпортом. Флинг, начатый выше секции, к этому
   моменту уже летит, а браузер не подхватывает `scroll-snap-type`, появившийся
   посреди жеста. Пока секция была 9841 px, добросить до неё одним махом было
   невозможно, и дефект не проявлялся — сокращение пина его обнажило.

## Solution

`perAction` на мобильном 0.55 → 0.8 (675 px на действие, шаг снова стоит одного
свайпа). Переключение класса вынесено из обработчика прогресса в
`IntersectionObserver` с `rootMargin: 100%` — снап взведён за экран до входа в
секцию, когда жест ещё не начался. Десктоп не тронут: там свой JS-доводчик.

## Prevention

- Взводить CSS scroll-snap заранее (IO с запасом), а не по факту входа в зону:
  класс, появившийся посреди инерционного жеста, браузер игнорирует.
- Меняя длину скролл-секции, проверять, что шаг остаётся больше одного экрана —
  иначе снап остаётся единственной защитой, и его отказ сразу виден.
- Регрессия закрыта тестом `tests/layout.spec.ts` → «snap is armed before the
  section and every action costs a swipe».
