# Landing perf pass 2: HTTP/2, raw-PNG decor, render-blocking CSS

**Date:** 2026-06-14 13:00
**Files:** astro.config.mjs, src/components/ui/SectionDecor.{tsx→astro}, sections/{What,Order,Premium,FinalCta}.astro, nginx vhost (server), removed 5 dead PNGs
**Severity:** low (incremental — site was already LH 99 / LCP 1.7s)

## Problem

Post-launch perf review found three avoidable costs even though Lighthouse was already green:
1. New server served **HTTP/1.1** (the migrated certbot vhost had `listen 443 ssl;` without http2).
2. `SectionDecor` decor layers loaded **full-size original PNGs** (used `ImageMetadata.src`), not optimized webp.
3. A **render-blocking** `<link rel="stylesheet">` for ~11 KB of CSS.
4. ~6.6 MB of **dead PNGs** (hero-master, hero-printer-*, kling-*) shipped in the build after the 3D hero was removed.

## Root Cause

- HTTP/2: certbot's nginx installer writes `listen 443 ssl;` (no http2 token); nobody added it. The migration copied that vhost verbatim.
- Raw PNGs: `SectionDecor` was a **React island** that built `<img src={asset.src}>` at runtime. `astro:assets` optimization (`<Image>` / `getImage`) is build/SSR-only and cannot run inside a client island, so the component fell back to the unoptimized original.
- CSS: Astro's default `inlineStylesheets: 'auto'` only inlines stylesheets under ~4 KB; the combined CSS exceeded that and was emitted as a linked file.
- Dead PNGs: `import.meta.glob('./engravings/*.png', { eager:true })` pulls every PNG into the build regardless of use.

## Solution

- nginx: `listen 443 ssl http2;` (+ IPv6) on the live vhost, reload — ALPN now negotiates `h2`.
- `SectionDecor.tsx` → `SectionDecor.astro`: render each layer as `<Parallax client:visible><Image …/></Parallax>` — the `<Image>` is Astro-rendered (build-optimized webp at display width), the Parallax island only carries motion. This is the same "Astro-optimized child inside a motion island" pattern used for Order/Premium art. Consumers import the `.astro` and drop `client:visible` on the (now non-island) SectionDecor.
- `astro.config.mjs`: `build.inlineStylesheets: 'always'` — all CSS inlined, no blocking request.
- Deleted the 5 unused source PNGs → dist PNG weight 8.5 MB → 1.84 MB.

## Prevention

- **Never optimize images inside a client island** — `astro:assets` is server-only. Render `<Image>` in Astro and pass it as a child/slot into the interactive island.
- After any **certbot** vhost generation, add `http2` to the `listen 443` line (certbot omits it).
- Audit `import.meta.glob(eager)` asset folders after removing features — unused files still ship.
- For content-focused Astro sites, prefer `inlineStylesheets: 'always'` (CSS is tiny) to kill render-blocking requests.
