## Запросы пользователя (с фото мобайла)
1. **ПРОБЛЕМА 1 — мобильный блок «болтается».** У телефона слишком много пустого места снизу; текст-описание под телефоном почти не виден (он bottom-anchored, уезжает к нижнему краю вьюпорта / частично за фолд) И анимированно меняет opacity/transform → тяжело читать. Нужно: телефон + текст как **единый плотный блок по центру**, текст **сразу под телефоном** (не у нижнего края, не в пустоте), анимацию появления текста убрать/ослабить (без translate-дрейфа).
2. **ПРОБЛЕМА 2 (главная) — нет брейкпоинтов.** Пользователь НЕ почувствовал остановок между фазами: весь блок (Колоды→Игра→Своя колода) проскакивается за один быстрый скролл. Прошлое dwell-плато визуально не дало ощущения «стоп». Нужно, чтобы скролл **всегда доводился к центру фазы при отпускании** и фаза фиксировалась.

## Решение по снапу (выбор пользователя)
**Доводка по отпусканию (программный snap-on-idle), на мобиле И десктопе.**

### Ключевой факт из кода (снимает риск конфликта)
`SmoothScroll.tsx:21` инициализирует Lenis **только** `if (!reduced && !small)` → **на мобиле Lenis ВЫКЛЮЧЕН**, страница на нативном скролле. Значит:
- **Мобайл (приоритет):** нет Lenis → нативный `window.scrollTo({behavior:'smooth'})`, никаких конфликтов.
- **Десктоп:** Lenis активен и владеет скроллом → доводим через `lenis.scrollTo`, чтобы не драться с инерцией. Инстанс Lenis — локальная переменная в замыкании `SmoothScroll`, наружу не отдан → нужно выставить его через модульный синглтон (`setLenis/getLenis` в `lib/smooth-scroll.ts`), без `window.*`.

Нативный CSS `scroll-snap-type` отвергнут: на десктопе конфликтует с Lenis, `mandatory` «залипает» и ломает свободный выход из секции; программный snap даёт полный контроль и единое поведение.

## Контекст файлов
- `ThroughPhone.tsx`: `useScrollScene(['start start','end end'])`; `pinned = mounted && !reduced && allFrames`; `scrubSeg = small?0.8:0.95`; `sectionStyle height = (1+n*scrubSeg)*100svh`; pinned sticky stage `height:100dvh`; `apply()` считает `f=p*n`, плато активности панелей/canvas, phone X-slide (десктоп), derived `localP` на сегмент → `CanvasSequence`. Центры фаз: `f ∈ {0.5,1.5,2.5}` (n=3).
- `ThroughPhone.css` (мобайл ≤860): `.tp-phone top:calc(env(safe)+54px)` (top-anchored), `.tp-panel top:auto; bottom:clamp(...)` (bottom-anchored ← источник ПРОБЛЕМЫ 1), `.tp-screen --sh clamp(440px,66svh,600px)`.
- `lib/smooth-scroll.ts`: `createLenis()` (duration 1.05, кастомный easing). `DEBUG_SCROLL = import.meta.env.DEV`.
- `components/ui/SmoothScroll.tsx`: создаёт/уничтожает Lenis в useEffect; rAF-loop; anchor-click → `lenis.scrollTo` или нативно. Lenis HARD-guarded по `small`/`reduced`.
- `lib/use-scroll-scene`, `lib/scroll-progress` (ScrollValue: `get()`/`on('change')`).

## Tasks

- [x] **SN-1 — Мобайл: телефон+текст единым плотным блоком по центру (ПРОБЛЕМА 1).**
  `ThroughPhone.css` (мобайл ≤860, ≤380) + `ThroughPhone.tsx` (small-ветка). Текст закрепить **сразу под телефоном** (`.tp-panel top: calc(<phone-top> + <phoneHeight> + gap)`), убрать bottom-anchor (`bottom:clamp` → убрать), убрать нижний пустой зазор; пару «телефон+подпись» центрировать как единый блок (уменьшить `--sh`, напр. `clamp(380px,56svh,520px)`, сдвинуть телефон от самого верха к центру). В `apply()` small-ветке **убрать translate-дрейф** панели (`translate(-50%, (1-o)*18px)` → только opacity, можно резче), чтобы текст не плыл при чтении. Итог: нет мёртвого пространства, текст полностью виден, читается стабильно.

- [x] **SN-2 — Отдать инстанс Lenis наружу (под снап).**
  `lib/smooth-scroll.ts`: модульный синглтон `let _lenis; setLenis(x); getLenis()`. `SmoothScroll.tsx`: `setLenis(lenis)` сразу после `createLenis()`, `setLenis(null)` в cleanup. На мобиле/reduced `getLenis()===null` (Lenis не создаётся) — это корректно, контроллер снапа уйдёт в нативный `scrollTo`. Без `window.*`.

- [x] **SN-3 — Контроллер snap-on-idle в ThroughPhone (ядро ПРОБЛЕМЫ 2).**
  `ThroughPhone.tsx` (опц. вынести в `lib/use-phase-snap.ts`). Активен только при `pinned` и не reduced-motion.
  - **Idle-детект:** `scrollend` (где есть) + дебаунс-фолбэк по `scroll` (~140мс после последнего события) для Safari/старых.
  - **Снап:** если `sectionTop ≤ scrollY ≤ sectionTop+range` — считаем `f=p*n`, ближайший центр `c=round(f-0.5)+0.5 ∈ {0.5,1.5,2.5}`, `target=sectionTop+range*(c/n)`. Если `|scrollY-target| > 6px` И `< ~0.9*segmentPx` (не перепрыгивать через фазу) — анимируем: десктоп `getLenis()?.scrollTo(target,{duration:0.6})`; мобайл/без Lenis `window.scrollTo({top:target,behavior:'smooth'})`.
  - **Гарды:** отмена/скип, если до завершения снапа пришёл новый `wheel/touchstart/scroll` (не драться с пользователем мид-скроллом); не снапить за пределами секции (выход к Decks/What свободен); один снап на жест (дебаунс); reduced-motion → снапа нет. `apply()` (scrub/плато) не трогаем — снап правит только финальную позицию.

- [x] **SN-4 — Баланс scrubSeg ↔ сила/порог снапа.**
  `ThroughPhone.tsx`. С реальным снапом гипертрофированное плато больше не нужно — пересбалансировать длину сегмента (`scrubSeg`) и порог снапа так, чтобы: (a) 3 фазы чётко различимы и фиксируются на отпускании, (b) доводка короткая/комфортная (не длинный рывок), (c) Decks не появляется слишком поздно (≈≤4 экрана секции). Проверить пиксельную математику порога на 390 и 1440; убедиться, что вход/выход секции не «залипает».

- [x] **SN-5 — Проверка Playwright (390+1440) + деплой.**
  - **390** (нативный скролл, Lenis off): скролл по блоку, отпускание в случайных точках → страница доводится к ближайшему центру фазы каждый раз; текст плотно под телефоном, полностью виден, без мёртвого зазора снизу и наложения, не плывёт при чтении.
  - **1440** (Lenis on): отпускание → доводка к центру через Lenis; side-by-side переезд телефона + плато панелей целы; снап не залипает на входе/выходе секции.
  - Консоль чистая; reduced-motion → снапа нет, стек-фолбэк ок.
  - `bash scripts/deploy.sh` (LANDING_SSH_PASS + NL_SSH_PASS) → оба зеркала. Перед финальным деплоем подтвердить визуал.

## Открытые вопросы / риски
1. `scrollend` неравномерно поддержан (Safari iOS позднее остальных) → обязателен дебаунс-фолбэк по `scroll`; проверить на мобильном Safari (Playwright это эмулирует ограниченно — финальная проверка на реальном телефоне желательна).
2. Снап не должен мешать обычной навигации по якорям (`SmoothScroll` anchor-click) — снап активен только в pinned-диапазоне; вне его выход свободен.
3. Десктоп: `lenis.scrollTo` во время остаточной инерции — задать короткий `duration` и гард на новый ввод, чтобы не было двойной доводки.
4. Возможный край: очень быстрый flick через всю секцию — снап доводит к ближайшему центру в момент idle (это и есть желаемое «остановись на логическом блоке»).
