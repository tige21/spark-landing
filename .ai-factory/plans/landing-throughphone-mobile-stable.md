## Корень бага (из /aif-explore)
- Я завязал РАЗМЕР телефона (`--sh`) и сцену на **`dvh`** → `dvh` меняется при показе/скрытии адресной строки → телефон РЕСАЙЗИТСЯ (баги «разный вид вниз/вверх», «слишком сильно ресайзится»). В разных браузерах строка ведёт себя по-разному.
- `svh` стабилен (константа), но если ВСЁ в svh — снизу остаётся зазор когда строка спрятана (исходная жалоба).
- Уточнённое решение (лучше «центрирования»): **размер телефона — в `svh` (стабильный, НЕ ресайзится), а высоту сцены и нижний якорь — в `dvh` (телефон садится к РЕАЛЬНОМУ низу, нет зазора).** Тогда при тоггле строки телефон НЕ меняет размер (главная жалоба), лишь естественно доезжает к низу; меняется только незаметный средний отступ текст↔телефон.
- Отдельный баг: у `.tp-phone` нет дефолтного CSS `transform` → между гидрацией и первым JS-`apply()` кадр без центрирующего translate → «выезд из левого угла».

## Контекст (из кода)
- `ThroughPhone.tsx`: `stageStyle` pinned `height:'100dvh'`; `.tp-phone` `position:absolute; left:50%`; JS `apply()` пишет `transform: translate(calc(-50% + sideX*d), -50%)` (десктоп) / `translateX(-50%)` (мобайл) — только в `useEffect` после гидрации; activeSeg lazy.
- `ThroughPhone.css` мобильный (`≤860`): `.tp-eyebrow{display:none}`, `.tp-panel{top:safe+54}`, `.tp-phone{bottom:clamp(xs,1.5dvh,sm); padding:9px}`, `.tp-screen{--sh:clamp(480px,70dvh,640px)}`; `≤380`: `--sh:64dvh`.
- Десктоп размеры — базовое правило `.tp-screen{--sh:clamp(440px,64svh,580px)}` (svh, не трогаем; на десктопе адресной строки нет).
